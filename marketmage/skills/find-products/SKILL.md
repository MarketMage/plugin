## 1. Ask only for

- **The niche or category:** "kitchen", "dog accessories", "skincare".
- **The marketplace:** from the user's words (`references/running.md`, "Country"); US by default; GB, DE, FR and others for Amazon.
- **Optional:** the price range they want to sell in.
- **The profile, if there isn't one and it hasn't been offered in this chat:** its two quick questions (how they'd sell, then the budget band), in the same message as the estimate, skippable, once per conversation (`references/judgement-answer.md`, "Asking for the profile"). The lens changes what is searched, so ask before the runs when it costs nothing to wait; if they skip, search for any seller and don't offer it again. **Except a quick one-off read** the user asked for directly (one TikTok list, one trends check: under about USD 0.10): don't put the profile questions before it. Over USD 0.05, give its estimate and wait for the yes; under it, just run it, with no cost said; and offer the profile in one line after the answer (`references/running.md`, "Before any run", item 1: the one exception to "Asking for the profile").

- **A profile found after the yes** (the notebook's status record, read with the first runs: `references/notebook.md`, "Is it on?") counts as a profile from then on (a different profile the user says in this chat wins, and is saved with `upsertProfile`: `references/notebook-use.md`, "A profile said in this chat that differs from the saved one"): before writing the answer, read `references/judgement-profile.md`, `references/judgement-for-you.md` and the chosen lens's file in one batch, and the answer carries its "For you" column, with no profile offer. A lens's extra runs are offered after the answer, never run without a yes.

## 1c. The sources, by channel

Each channel reads the sources its buyers act on, so an idea can be confirmed from more than one side (owner's design, 9 Nov 2026: "selling on TikTok and advertised for 60+ days" says more than any one chart). The channel comes from the lens (`references/find-products-lenses.md`, Step 1b) or the request ("dropship with Facebook ads", "I sell on Amazon FBA", "on Etsy"); when neither says, the general blend.

| Channel | Round 1, together | Round 2, together, on the product types round 1 surfaced (up to 5) |
| --- | --- | --- |
| **Dropship, or an own store with ads** (the cold-traffic lens, or a request that says so) | TikTok Shop; Meta ads that have lasted (35+ days) | the AliExpress single-unit check (MOQ 1, the unit price before shipping, order counts where AliExpress shows them); Trends |
| **Amazon** (FBA, or own stock, dropship or print on demand sold on Amazon) | Best Sellers | the competition check (the top 10's monthly sales floor, review depth); Trends |
| **Etsy or eBay** (the Marketplace lens on Etsy or eBay) | their marketplace's search for the niche, with listing rows | Trends |
| **Makers** (the maker lens) | Trends on what their craft could make (`references/find-products-lenses.md`, Step 1b) | their marketplace's read on the top 3 (Etsy unless they name another) |
| **General** (no profile, the general lens, own stock or print on demand off Amazon without ads) | Best Sellers; TikTok Shop | Trends |

- **Product types for round 2** come from round 1's relevant rows (TikTok titles, the lasting ads' text and landing pages, the chart's titles, the marketplace's titles): the product types that most rows point to, the ones two sources share first.
- **Outside the US** TikTok Shop isn't read (`references/known-limits.md`); for dropship the Meta ads read stands in for felt want, with TikTok's ad library added in the EU, the UK and Switzerland (`platforms: ["meta", "tiktok"]`), and the lens's own outside-the-US read as `references/find-products-lenses.md`, "Step 2, cold-traffic offers" sets out.
- **A source the channel doesn't read by default** is offered after the answer in one line when it would add something ("Want TikTok Shop's sales as context?"), never run without a yes; one the user names ("also check TikTok") joins the plan and its approval line. A source the user excludes ("skip Amazon", "just TikTok") is left out; on the Amazon channel, when they skip the competition check, TikTok Shop is read in its place as a second demand source (context for an Amazon seller), so the ideas still have two sides.
- **An answer that changes the channel** (the approval was for one channel's sources, and the user's answer to the optional questions, "dropshipping with a Shopify store", "I sell on Etsy", picks another, often with "go ahead" in the same message): the new channel's reads are a new plan (`references/running-asks.md`, "A changed plan"). The "go ahead" covers them only when the new channel's estimate (the free-plan figure when higher) is at most the one approved and the "Reading … now" line names them ("Reading TikTok Shop, the Meta ads that have run 35+ days and AliExpress single units now: about USD 0.24, occasionally a little more if I need to dig deeper to answer you."); otherwise no run starts: one line names the new channel's reads with their estimate (step 2) and asks again ("For dropshipping I'd read TikTok Shop, the Meta ads that have run 35+ days, AliExpress single units and Trends instead of the Amazon chart. This costs about USD 0.26 (about USD 0.28 on Apify's free plan), occasionally a little more if I need to dig deeper to answer you. Go ahead?"). Never the new channel's sources on the old yes without saying so.
- **Within one reply** (`references/running.md`, "Tool calls: one reply, a budget"): the references in one batch, each round's runs started together and their reads made together with only the fields step 3 names; about 12 to 16 tool calls in all. A slow read (the AliExpress check, an Etsy search) starts first in its round, with `waitSecs: 0`, as `references/running-runs.md`, "Timing" sets out. When the reply might still run out, stop at a clean point with what is in and what is left, then "Say continue and I'll finish it"; never by dropping a source the yes covered.

**Backed by several sources.** An idea is backed by a source only when that source's own rows, checked for relevance as step 3 sets out, show it:
- **TikTok Shop:** relevant listings with 100+ units sold (lifetime);
- **Meta ads that have lasted:** an advertiser whose ad names it (in the ad's text, title or landing page, not only the niche's word) has kept it running 35+ days; say the longest, in plain words ("advertised for 60+ days");
- **AliExpress:** a matching offer sold one at a time (`moq1OfferFound: true`), with its orders only when the offer carries `ordersCount` (most AliExpress rows don't yet: then no order figure is said or guessed);
- **Amazon:** a relevant row in the chart's top 50, or a sales floor of 1,000+ units a month from the competition check;
- **Etsy or eBay:** 5 or more relevant listings, at least one with item reviews behind it;
- **Trends:** searches up 15% or more over 12 months.

The count of backing sources orders the ideas within the same favour (step 4, "Order"), and each idea's what-helps cell opens with its backing in a few plain words, its strongest number beside it ("selling on TikTok (4,100 sold) and advertised for 60+ days"); an idea one source shows says so ("TikTok only so far"). A source that wasn't read never counts against an idea.

## 3. Read the results

- **Best Sellers:** `rank`, `title`, `price`, `rating`, `reviewCount`, `daysOnChart` (check each title belongs to the niche; a department chart holds much else), and the `chart-summary` row (median price, brands, `newEntries`). A product new to the top 50 (`daysOnChart` low) is a sign of a chart that moves; offer the chart watch (step 5) to see new entries as they happen.
- **TikTok Shop:** `title`, `price`, `unitsSold` (lifetime), `shopName`, `brand`, and each keyword source's `relevantToKeyword` and `keywordWordsMissing`. **Check every row is the niche's product** (`references/running-results.md`, "Read the data like an analyst"): a shop that ranks for the keyword often brings its other products (a "lip gloss" search can return the same brand's deodorant and serum). `relevantToKeyword` is the actor's title check (every word of the keyword in the title), a clue, not a verdict: confirm it against the title, and keep a `false` row that is clearly the product under another name ("lip oil" for a gloss search, if the user would count it) and drop a `true` row that isn't. Use the keyword summary's `relevantToKeyword` totals (`products`, `unitsSoldTotal`, `unitsPerDayTotal`…, with its `relevanceBasis`) rather than the totals over every product, adjusted for any row you judged differently, and say how many were left out. If fewer than 5 relevant rows remain, say the TikTok signal is thin and offer a narrower keyword or more products.
  - **Units per day need two reads a few days apart:** this run gives lifetime `unitsSold`. Say so, and offer the TikTok watch (step 5), which reports units per day from its second run.
- **Trends:** the 12-month `summary.direction` and `changePercent` per product type, seasonal peaks, and **`relatedQueries_rising`**: rising searches are where angles and sub-niches show first, so they get their own column. When the rows are read, ask for `fields: "searchTerm,summary,relatedQueries_rising"` (plus `interestOverTime_timelineData` only when peaks aren't in the message).
- **Meta ads that have lasted** (`fields: "advertiser,text,title,landingUrl,firstShown"`, `limit: 30`): each row is an ad running 35+ days. Group the ads by the product they sell, read from the ad's text, title and landing page (a `/products/<name>` path names it); leave out ads that plainly sell something else (a vet clinic, a food brand for a toy search) or only name the niche, and say how many in the exclusion line. Per product: how many advertisers, and the longest-running ad's days (from `firstShown` to the date read). A product sold by ads for 35+ days is spend that pays its way, not proof for the user's store: say it as "advertised for 60+ days by 2 stores".
- **The AliExpress single-unit check** (`fields: "recordType,product,singleUnit,unitPriceMin,unitPriceMedian,moqMin,offers"` for the summaries; offers only when a summary needs checking, with `ordersCount`, `newShopperPrice`, `regularPrice` and `notes`): `singleUnit.moq1OfferFound` and `unitPriceMin` (what a returning buyer pays, never a new-shopper deal or the struck-through `regularPrice`: `references/running-runs.md`, "AliExpress prices: the unit price, and the new-shopper deal") per product type, as `suppliers` reads them (`offersRead: 0` is "no matching listing under this name", never a fail). An order count is said only from an offer's `ordersCount`; null, as on most AliExpress rows today, is never read as zero or guessed.
- **Etsy or eBay for the niche** (`fields: "recordType,title,price,seller,itemReviews,quantitySold,starSeller,listedAt"` on the listing rows, `limit: 48`): check each title is the niche's product; product types come from the titles, each with its listings, price band and Etsy's item reviews or eBay's `quantitySold` (Etsy shows no sales, so item reviews are the nearest sign of orders: say so once).
- **Which reads a run's status message replaces** (`references/running-runs.md`, "A run's status message: the numbers first"; read each run's message first):
  - **Trends:** its message stands in for the rows when it names every product type with its direction and change, and has a "Rising searches for" sentence for each (the rising-search column), and doesn't end `More in the dataset.`; its one peak per term is the peak over the 12 months. Otherwise read the rows: with 4 or 5 terms the message usually stops short. **The rising-search column, term by term:** from the message's `Rising searches for "<term>"` sentence when it has one for that term; for every other term, from the row's `relatedQueries_rising`, read before the answer is written, whatever else the message carries. A long message drops the rising sentences first, sometimes with no `More in the dataset.` at the end, so a term with no rising sentence has its rising searches **unread, not none**. A cell says "no rising searches yet" only when that term's row was read and its `relatedQueries_rising` is empty; never "none returned", "none", "—" or a blank for a term whose row holds them. The calibrated comparison's "On one scale" sentence gives the ranking when it names every idea.
  - **Competition check:** its message stands in when it carries each keyword's sentence and its "also:" sentence (`sellerHhi` and the under-100 count, for Review depth and Concentration); with several keywords those usually don't fit, so read the rows.
