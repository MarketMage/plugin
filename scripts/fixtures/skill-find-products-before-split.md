# Find products

Turn the user's niche into a short, scored map of product ideas, and find the ones worth checking together. Read these first:
- `references/judgement.md`: the core: the rules and the signal thresholds. **Follow it, and each part below.** Its other parts are read only at the step that needs them: `references/judgement-answer.md` (the tone, the answer structure, and asking for the profile) with `references/judgement-first-answer.md` (the first answer's parts, notation by experience, labels against counts, weighting by channel, one demand statement, relevant rising searches) before scoring and writing the answer, or with the first batch when the profile is to be offered; `references/judgement-ladder.md` (the related versions ladder, the watches) once the verdict is known; `references/judgement-profile.md` (the profile, choosing the lens) when there is a profile (asking for one is in `references/judgement-answer.md`); with a profile, once the lens is chosen, `references/judgement-for-you.md` and the chosen lens's file only (`references/judgement-lens-cold-traffic.md` with `references/judgement-lens-cold-traffic-count.md`, `references/judgement-lens-marketplace.md`, `references/judgement-lens-own-stock.md`, `references/judgement-lens-maker.md` or `references/judgement-lens-general.md`; plus `references/judgement-lens-goals.md` when the goal is side income or brand); `references/judgement-abroad.md` (margins outside the US or across currencies, EU risk notes) before working such a margin; `references/judgement-saturation.md` (Where you'd compete) only through the cold-traffic lens, when that read is made or offered. Never read a lens file for a lens the user isn't on. **When the first message already gives the profile** (or the chat holds one), read the core and every part this job will use (the answer file, ladder, profile, for-you, the lens's file or files, the goals file when the goal is set, saturation through the cold-traffic lens, and `references/judgement-abroad.md` outside the US) in that one first batch, with `running.md` and `costs.md`.
- `references/running.md`: costs, caps, tools, secrets, and the runs already made in this conversation.
- `references/notebook.md`: the opt-in notebook, when the user asks to be remembered or keeps one (then `references/notebook-use.md` before any notebook call).
- `references/costs.md`: the prices.

**Read once, together:** a reference already read in this conversation (by this skill or another MarketMage skill: their copies are the same text) is not read again. Read the references a step needs in one batch of parallel reads, never one after another.

**Reading a run's record** (`RUN_SUMMARY`, `DIGEST.md`): `get-key-value-store-record` with `keyValueStoreId` set to the run's `defaultKeyValueStoreId` (from `call-actor` or `get-actor-run`) and `recordKey` set to the key; never without `keyValueStoreId` (`references/running.md`, "Running").

## 1. Ask only for

- **The niche or category:** "kitchen", "dog accessories", "skincare".
- **The marketplace:** from the user's words (`references/running.md`, "Country"); US by default; GB, DE, FR and others for Amazon.
- **Optional:** the price range they want to sell in.
- **The profile, if there isn't one and it hasn't been offered in this chat:** its two quick questions (how they'd sell, then the budget band), in the same message as the estimate, skippable, once per conversation (`references/judgement-answer.md`, "Asking for the profile"). The lens changes what is searched, so ask before the runs when it costs nothing to wait; if they skip, search for any seller and don't offer it again. **Except a quick one-off read** the user asked for directly (one TikTok list, one trends check: under about USD 0.10): don't put the profile questions before it. Over USD 0.05, give its estimate and wait for the yes; under it, just run it, with no cost said; and offer the profile in one line after the answer (`references/running.md`, "Before any run", item 1: the one exception to "Asking for the profile").

## 3. Read the results

- **Best Sellers:** `rank`, `title`, `price`, `rating`, `reviewCount`, `daysOnChart` (check each title belongs to the niche; a department chart holds much else), and the `chart-summary` row (median price, brands, `newEntries`). A product new to the top 50 (`daysOnChart` low) is a sign of a chart that moves; offer the chart watch (step 5) to see new entries as they happen.
- **TikTok Shop:** `title`, `price`, `unitsSold` (lifetime), `shopName`, `brand`, and each keyword source's `relevantToKeyword` and `keywordWordsMissing`. **Check every row is the niche's product** (`references/running.md`, "Read the data like an analyst"): a shop that ranks for the keyword often brings its other products (a "lip gloss" search can return the same brand's deodorant and serum). `relevantToKeyword` is the actor's title check (every word of the keyword in the title), a clue, not a verdict: confirm it against the title, and keep a `false` row that is clearly the product under another name ("lip oil" for a gloss search, if the user would count it) and drop a `true` row that isn't. Use the keyword summary's `relevantToKeyword` totals (`products`, `unitsSoldTotal`, `unitsPerDayTotal`…, with its `relevanceBasis`) rather than the totals over every product, adjusted for any row you judged differently, and say how many were left out. If fewer than 5 relevant rows remain, say the TikTok signal is thin and offer a narrower keyword or more products.
  - **Units per day need two reads a few days apart:** this run gives lifetime `unitsSold`. Say so, and offer the TikTok watch (step 5), which reports units per day from its second run.
- **Trends:** the 12-month `summary.direction` and `changePercent` per product type, seasonal peaks, and **`relatedQueries_rising`**: rising searches are where angles and sub-niches show first, so they get their own column. When the rows are read, ask for `fields: "searchTerm,summary,relatedQueries_rising"` (plus `interestOverTime_timelineData` only when peaks aren't in the message).
- **Competition check** (the `keyword-summary` rows): `medianReviews`, `under100Reviews`, `top3SellerShare`, `sellerHhi`, the `priceP25`…`priceP75` band, and `salesFloor` (the top 10 organic results' "bought in past month" floor: `unitsPerMonthMin`, `revenuePerMonthMin`). Quote the floor as "at least 8,000 units, about USD 160,000 a month across the top 10", never as an estimate of sales (`references/judgement.md`, "The sales floor is a floor"). `marketplaceFees` gives Amazon US's referral rate (quote it from that row, never from this text) when the user asks what a sale pays out; the FBA fee comes with `validate`. **On Etsy or eBay** (the Marketplace lens's own read): no `salesFloor` (neither shows monthly sales: Demand level is `unknown` for them, with the Amazon and TikTok figures as labelled context); Concentration for them is the top 3 sellers' share of the listing rows that are the product (checked against the title; 10 or more such rows, else `unknown`, "sample too thin to score"; top-3 share thresholds only), never the summary's `top3SellerShare` or `sellerHhi`; the price band, and `marketplaceFees` for that marketplace; its `medianReviews` are the shop's or the seller's feedback, not the product's, so it isn't scored as review depth.

## 4. Score, then present

Score each idea on up to four signals, with the thresholds in `references/judgement.md`:
- **Chart:** Best Sellers review depth (`reviewCount` median of its rows under 500 favours, over 3,000 against) and recent entries;
- **Demand level:** TikTok `unitsSold` of the idea's top listings (1,000+ favours, under 100 against), or, when competition was checked, the Amazon sales floor of its top 10 (10,000+ units a month favours, under 1,000 against); `unknown` when neither was read (outside the US, only the sales floor can read it);
- **Demand trend:** its Trends direction over 12 months (+15% or more favours, −15% or less against);
- **Competition,** if checked: review depth and concentration from its keyword summary. For an Etsy or eBay seller, on their marketplace: review depth is not counted (the summary's `medianReviews` are the shop's or the seller's), and concentration comes from the listing rows that are the product (10 or more), never from the summary's `medianReviews`, `top3SellerShare` or `sellerHhi`; `unknown` if not checked.

Give each idea its `for` and `against` counts. An idea is one the data **favours** when its counts would read Strong, **against** when they'd read Not this version (4 or more against, or two or more against and more against than for: `references/judgement-first-answer.md`, "Labels follow the counts and the budget gate"), and **mixed** otherwise. Each idea has **one** demand-trend statement, its 12-month figure, the same everywhere it appears, with a stand-in term named as one ("One demand statement per idea"). Then:
- **A question in the user's message is answered first,** in plain words, before the opening line and the table (`references/judgement-tone.md`, "Answer the user's question first"); the table follows. The reply is sized to what was asked ("Size the reply to the question"), and a newcomer gets plain words for each term the first time ("Plain words for a newcomer").
- **Open on the best opening found** (`references/judgement-tone.md`, "Open on the best opening"): the first sentence names the strongest lead (for them, through the lens, when there's a profile; through the cold-traffic lens, the table's top row) and its number ("The strongest lead is a 40-piece meal-prep set: 34,876 units sold on TikTok Shop at USD 30.99."), even when no idea came out clearly ahead; then say in a line why it leads. Never open with a count, or with what didn't come out ahead. If the user named a hunch about the niche, give credit where a number backs it.
- **The visual moment, between the opening and the table** (`references/running.md`, "Explaining results": "One visual, where it helps"; only where you can draw one, and otherwise nothing about it is said): **the ideas side by side**, one horizontal bar per idea in the table, in the table's order, all on one measure: the TikTok `unitsSold` (lifetime) of the idea's top relevant listing when TikTok was read for the ideas, else the Amazon `salesFloor.unitsPerMonthMin` when competition was checked; an idea without that number is named under the chart as "not read", never drawn as zero. Each bar is labelled with the idea and its number, and coloured by its for/against count (favours green, mixed grey, against red), with the word beside the number as well. Caption: the measure in words ("TikTok Shop US, lifetime units of the top listing" or "Amazon US, at least this many a month across the top 10") and the date read.
- **A table of 5 to 8 ideas** (under 10 rows): idea, typical price, for/against, the number that most favours it, the number that most goes against it, and a rising search for it (from the rows when the message lacks it: step 3; only one about that idea's own product, never a joke, novelty or political search, and with "from a small base" beside a low-volume, breakout or +500% figure: `references/judgement-first-answer.md`, "Rising searches, in every answer"). ## 5. Ongoing: the weekly opportunity digest, sales per day and chart moves (watchlists)

Offer these with the answer when the user wants to keep an eye on the niche ("once or ongoing", `references/running.md`). All are Watch Digest watchlists (`references/watchlists.md`), so their results go to "your briefing in Claude, on request or on a Monday schedule" (sent to Slack, Discord, Teams or email only when the user asks), and the `watchlists` skill reads them.

**The weekly opportunity digest** (the one to offer first: new rising products in the niche, every week), task `cw-opps-<niche>`:
- **Input:** `cleanpull/watch-digest` with, in one task:
  - `trendsTerms`: the niche's product types and the rising searches this run found (at most 100; 5 to start), `trendsGeo` (the marketplace country, `US` by default), `trendsTimeRange: "past-90-days"` (suits a weekly digest), `trendsMinInterestChangePercent` (50 by default: a term's latest quarter of the period against its earliest);
  - `chartCategories` (the department read in step 2), `chartTypes: ["new-releases"]` (add `movers-and-shakers` if the user wants climbers too), `chartMarketplaces`, `chartMaxItemsPerChart: 50`;
  - `tiktokKeywords` (US only; the niche term), `tiktokMaxProductsPerKeyword: 20`;
  - `monitorName: "<niche>"`, `title`, `maxRunCostUsd`.
- **What it reports:** the digest opens with an **Opportunities this week** section: new rising searches and breakouts first, then new entries on the chart, then TikTok Shop products selling faster. Every other change follows by watcher. The first run is the baseline (rising searches remembered, chart and TikTok recorded): rising searches and chart entries start with the second run, TikTok products speeding up with the third (the second gives the first units per day). Interest moves are Google's relative interest (0 to 100), not search counts.
- **Cost per run, weekly** (`references/costs.md`): digest USD 0.005 + USD 0.00025 per item (term, chart, keyword); each Trends term USD 0.0015 every run; the chart and TikTok parts as below. **Example:** 5 terms, the New Releases chart of one department at 50 ranks, and 1 TikTok keyword: first run ≈ 0.005 + 7 × 0.00025 + 5 × 0.0015 + 50 × 0.0015 + 0.002 + 0.06 ≈ **USD 0.15**; later runs ≈ 0.005 + 0.002 + 0.0075 + about 0.04 for the chart's moves + up to 0.06 for TikTok ≈ **USD 0.115 a run, about USD 0.50 a month**. Without TikTok (outside the US, or to keep it light) about USD 0.25 a month. Daily isn't needed: the section is built for a week.
- **`maxRunCostUsd`:** about 1.5× a typical run (USD 0.17 for the example); the baseline run uses the first-run cap (about USD 0.23).
- **Steps:** follow `references/watchlists.md` (cost, yes, task, baseline, schedule weekly, where the results go). If the user keeps a notebook, link the watch to the niche's idea entry (`references/notebook.md`).

**TikTok Shop sales per day** (US only), task `cw-tiktok-<name>`:
- **Input:** `cleanpull/watch-digest` with `tiktokKeywords` (at most 100), `tiktokMaxProductsPerKeyword` (20 by default), `monitorName: "<name>"`, `title`, `maxRunCostUsd`.
- **What the digests report:** the top products' units per day from the second run; from the third, products speeding up or slowing down; products new to the keyword; price moves.

Weekly or every few days is enough to see a trend.
